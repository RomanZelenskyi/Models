# MDIAPP — перенос с Delphi на C#

Исходники: `D:\RABOTA\Delphi\260115`. Целевой проект: `MDIAPP.dpr`.

**Основной рабочий цикл Main/ChildWin и редакторы перенесены в C#/WPF. Численное сравнение с Delphi пока заблокировано: исходные расчётные EXE аварийно завершаются в проверяемой среде. Подробности — SOLVER_VALIDATION.md.**

## Запуск

Проект предназначен для Visual Studio 2019 (16.3 или новее), C# 8.0 и .NET Framework 4.8. В установщике Visual Studio нужны компоненты «Разработка классических приложений .NET» и .NET Framework 4.8 Targeting Pack.

Откройте `Mdiapp.sln`, назначьте **`Mdiapp.Wpf`** запускаемым проектом и нажмите F5. Это стандартный WPF без Telerik и других платных компонентов. Проекты имеют обычный формат .NET Framework, не требуют .NET 10 SDK или пакетов NuGet.

`Mdiapp.Core` содержит общую логику, `Mdiapp.Checks` — проверки. В solution остались только WPF, Core и Checks. Комплектные настройки WPF лежат в общем каталоге `Data` и копируются рядом с EXE.

Сборка из Developer PowerShell / Developer Command Prompt для VS 2019:

```powershell
msbuild Mdiapp.sln /t:Rebuild /p:Configuration=Release
.\Mdiapp.Wpf\bin\Release\MDIAPP.exe
.\Mdiapp.Checks\bin\Release\Mdiapp.Checks.exe "D:\RABOTA\Delphi\260115\sp-12\datar"
```

## Реализовано

- WPF: главное окно на XAML, рабочие вкладки вместо MDI, стандартные DataGrid, меню и диалоги. Подключены существующая логика Unit2, Unit3, создание двигателя Unit4, импорт Unit5/6, язык Unit7, настройки Unit8, путь Unit9, двигатель Unit10, редакторы Unit11–40, полная модель INM и COD. В WPF редакторы организованы иначе: параметры файла 30 по вкладкам, PREG и условия пары 31–32 отдельными таблицами/вкладками, описания входных файлов Unit3 — общей таблицей ключей INI. Платные библиотеки и WindowsFormsHost не используются. Числовые привязки учитывают региональные настройки Windows.
- Проверки WPF: загрузка главного XAML и редакторов, сохранение изменённой таблицы отборов, окна выбора языка/двигателя и настроек экспорта, создание двигателя с преобразованием PNG в BMP и импорт тестового снимка старых настроек. Все операции проверки записи выполняются во временных папках. Запуск расчёта, чтение результатов и экспорт подключены в рабочей вкладке проекта.

- Unit2: постоянное значение, приращение по точкам, степенная зависимость. При t=0 сохранена ветвь исходника a+k2. Массивы C# имеют индексы от нуля.
- Unit41: кодирование и декодирование COD, Int32 little-endian, ключ из 20 значений и разделитель -777. Текстовая кодировка Windows-1251, конец строки CRLF. Повреждённые записи отклоняются.
- Чтение и запись INI с ключами без учёта регистра. При редактировании сохраняются комментарии и неизвестные секции; изменённые строки и новые ключи записываются в стандартном формате.
- INM: полная модель ProjectDocument, задачи/конфигурации/условия/флаги, режимы, идентификаторы аргументов, точности, выходные параметры, динамические факторы, управляющие параметры, поправки узлов и многопараметрические поправки. Без изменений сохраняются исходные байты; неизвестный хвост сохраняется. Старый формат с одним рядом поправок поддерживается.
- Контрольные примеры формул и двоичного формата без внешних пакетов.
- Unit7: отдельное окно языка через «Инструменты → Настройки». Меняет только `Interface/lang` и `Interface/help`, не меняя двигатель. Надписи берутся из `forms/n7`, `Setups/l9`, `Setups/b1`; уведомление о перезапуске — из `constants/n12`. Текущий язык интерфейса остаётся активным до перезапуска. OK без смены языка не записывает файл; отмена не сохраняет изменения. Для отсутствующего файла `menu.ini` выбранного языка OK отключён. Настройки записываются в `models.ini рядом с EXE` с резервной копией; исходный файл не изменяется. Выбор двигателя в Unit3 сохраняет ожидающую перезапуска смену языка.
- Коды двигателей берутся из `nnN`, а не из позиции в списке. Главное меню частично локализовано из исходных INI. Китайский язык объявлен в исходных настройках, но его `menu.ini` и `jobs.ini` отсутствуют.
- Unit21: редактор входного файла типа 51, четыре числовых поля шириной 8 символов с 3 знаками после запятой. Сохраняется числовая культура Windows, как у Delphi. В отличие от исходника, слишком большие значения отклоняются вместо обрезки числа.
- Каталог `Data` содержит копии исходных настроек, переводов и описаний файла типа 51. Они копируются в выходную папку при сборке.
- Unit3: окно настройки моделей. Открывается через «Инструменты → Настройка моделей (Unit3)…». Реализованы таблица двигателей, задачи с EXE и PREG, конфигурации, выбор параметров/управляющих параметров/характеристик, условия, разное, порядок подключаемых типов файлов, динамические факторы и графики. Реализованы настройки файлов 24, 28, 29/40, 30, 31/32, 41, 51, признаки создания новых файлов, параметр времени, PREG, param.dat и rez.dat.
- Настройки Unit3 хранятся в `каталоге рядом с EXE`. При первом запуске туда копируются комплектные файлы; существующие пользовательские настройки при сборке и запуске не заменяются. «Сохранить всё» создаёт `.bak` и обновляет два файла `jobs.ini.cod` в формате Unit41. Исходная папка Delphi не изменяется.
- Unit4: создание двигателя через кнопку «Создать двигатель…» в окне Unit3. Семь полей: имя папки, код 1–100, описание, папка расчётных файлов, папка данных, необязательный файл параметров и обязательное изображение. Папки источников можно оставить пустыми. Создаются `bin`, `data`, `datar`, `result` и папка текущего языка, начальные `jobs.ini`, `misc.ini`, `namepar1.txt` и `PROJECT.BMP`. Копирование рекурсивное; изображение преобразуется в BMP независимо от наличия файла параметров. Без файла параметров записывается `-1`. Регистрация в каталоге выполняется после успешного копирования; при ошибке незавершённая папка удаляется. Повтор имени/кода и недопустимые пути отклоняются. Копирование выполняется в фоне с индикатором прогресса; во время операции закрытие формы отключено.
- Unit5: импорт через кнопку «Импортировать…» в Unit3. Выбор исходного проекта выполняется отдельным окном Unit6: список берётся из `HKCU\Software\KhAI (AEDLab)\Models\Settings\ProjectList`, настройки — из ветки выбранного проекта (32-битное представление реестра). Реестр открывается только для чтения. Папку старых проектов можно выбрать вместо стандартной `C:\Models`. После выбора проекта заполняются семь полей импорта; новое имя и код можно изменить. Переносятся задачи `EXE/тип файлов/PREG`, конфигурации, параметры, характеристики, пункты «Разное» и все 13 полей графиков. Папки `datar` и `result` берутся из исходного проекта даже при изменении нового имени. Результат сохраняется в пользовательском каталоге, как у Unit4; ошибки копирования не оставляют зарегистрированный двигатель.
- Импорт Unit5 сохраняет начальное условие `0`, как исходник Delphi; параметр времени получает значение 385. Разделение списка параметров выполняется по словам и поддерживает четырёхзначные номера. В `misc.ini` записываются имеющиеся пункты с сохранением их номеров. Пустые списки обрабатываются корректно. Более 200 графиков отклоняется из-за ограничения текущей модели Unit3. Для запуска импорта нужны настройки старой программы в реестре данного пользователя. Автоматические проверки преобразования используют тестовый снимок этих настроек и временные файлы, не изменяя реестр.
- Таблицы WPF заменяют компоненты Delphi/DevExpress; выбор производится флажками, порядок меняется кнопками выше/ниже. Поиск параметров охватывает номер, символ, тип, величину, узел и название. Сохраняются исходные числовые идентификаторы. Пустые списки записываются корректно; разрешение полей 31/32 после шестой позиции отключается, как в Delphi.

## Границы переноса Unit3

Вызовы `Form4.ShowModal` и `Form5.ShowModal` перенесены в кнопки создания и импорта двигателя. Таблица двигателей редактирует каталог и описания; для создания папок и копирования файлов используйте соответствующие кнопки. Удаление записи из каталога не удаляет папку двигателя. Для конфигураций и задач разрешено удаление последней записи, чтобы не менять идентификаторы существующих моделей. Справочные коды типа/узла отображаются как коды; поиск заменяет прежние фильтры.

Изменения сохраняются по файлам с резервными копиями; многофайловая операция не является транзакцией. При ошибке записи следует восстановить затронутые файлы из `.bak`.

## Проверка совместимости

Main/ChildWin подключены к рабочей вкладке проекта. Неподключённых активных редакторов Unit2–Unit42 не осталось; about реализован. Unit1 не входит в MDIAPP.dpr, PDirSelected заменён стандартным выбором папки. Отключённые в исходнике ветки trial_on/trial_engine_on не включаются в полной сборке.

Не завершено численное сравнение полного расчёта: исходные Dross.exe, dinam.exe и kldm.exe не создают param.dat и завершаются с ошибкой в этой среде. Dross.exe также проверен на исходном входном файле и вне песочницы — результат тот же. Требуется рабочий расчётный EXE либо возможность пересобрать его исходники. Код подготовки и запуска проверен отдельным тестовым процессом. См. SOLVER_VALIDATION.md.

`delphi-modules.csv` содержит инвентаризацию исходных модулей. Оригинальные исходники и данные не изменяются.

Главное окно обновляет статус, а диалог открытия INM использует папку datar выбранного двигателя. Надписи соответствуют forms/n3, Setups/t11 и b1 исходного menu.ini.

## Unit11 — редактор файлов 31–32

Открытие: Инструменты → Редактор файлов 31–32 (Unit11). Выберите файл начальных значений типа 31 и файл пределов типа 32. Редактор использует настройки 31_32 текущего двигателя, общий Namepar.txt и дополнительный Namepar1.txt двигателя; дополнительные записи заменяют совпадающие общие номера. Доступны начальное значение, минимум, максимум, комментарии двух файлов, режимы PREG и три значения выбранного условия. Номера и справочные подписи не редактируются, строки резерва получают r/r1/r2 из INI и заблокированы. Первая группа параметров выделена цветом; визуальный разделитель не попадает в файлы.

Сохранение проверяет границы и формат 14 символов с 6 десятичными знаками. Значения, не помещающиеся в поле, отклоняются вместо обрезания. Файлы записываются как Windows-1251/CRLF с комментариями после ! и резервными копиями .bak. Оба файла сначала подготавливаются; при ошибке замены второго содержимое первого восстанавливается. Сохранить как запрашивает оба имени; отмена любого диалога не записывает файлы. Числа с точкой из исходных DAT читаются также при десятичной запятой Windows. PREG сохраняет собственные коды 0–3, включая разреженный набор. Выбранный при открытии двигатель должен соответствовать паре файлов.

## Unit42 — окно «Что нового»

Открытие: Справка → Что нового — Unit42. Документ задаётся Interface/new в models.ini и берётся из папки текущего языка. Русский и английский new.pdf включены в Data. После отключения окно остаётся доступным из меню. Открытие главного окна задано явно в App.OnStartup; WPF-ресурсы по-прежнему загружаются через App.InitializeComponent.

## Рабочая вкладка проекта — Main/ChildWin

Открывается через «Файл → Открыть проект INM» либо «Новый проект». Семь разделов: проект/расчёт, режимы/параметры, подключённые файлы, выходные параметры/поправки, редакторы DAT, результаты и графики. Задачи, конфигурации, условия и доступные флаги берутся из каталога двигателя. Первая строка таблицы режимов содержит номера параметров; -1 означает отключённый столбец. Поддерживаются до 10000 режимов и до 30 аргументов. Закон Unit2 можно применить к выбранному столбцу.

Редакторы DAT выбираются по типу файла и признаку new в inputfiles.ini. Они работают с отдельными копиями. Поправки активного проекта передаются в Unit27–Unit33 по номерам Delphi; списки аргументов учитывают активные параметры, неизвестный текущий номер сохраняется. При сохранении INM также сохраняются копии редактированных DAT с .bak; «Сохранить как» переносит подключённые файлы в соответствующую data-папку. INM и DAT сохраняются по отдельности: общий многофайловый откат не является транзакцией.

«Рассчитать» подготавливает отдельную папку с bin/data, копиями EXE/служебных файлов, подключёнными DAT и новым data.dat. Исторические результаты INM не записываются в data.dat; устаревшие param.dat/rez.dat удаляются только в копии. EXE запускается в подготовленном bin, интерфейс остаётся отзывчивым, доступна остановка. Проверяются код завершения и rez.dat (если включён в настройках); param.dat собирается в полные записи по списку выходных параметров. Папка двигателя и EXE задаются в проекте.

Результаты можно загрузить из param.dat или RES, отобрать параметры/режимы, строить графики по выбранным X/Y с дополнительной красной кривой. Колесо мыши меняет масштаб, перетаскивание с левой кнопкой перемещает график, двойной щелчок или кнопка сбрасывают вид. Экспорт TXT/HTML/RES учитывает Unit8: числовой формат, точность, транспонирование, исходные данные; HTML содержит SVG-графики. Доступны печать и предпросмотр текущих данных/графика.

Добавлены about с исходными сведениями о разработчиках, руководства русского и английского языков и локализация общих элементов. Комплект Data/sp-12 содержит исходные bin/data/datar и ресурсы форм; первоначальное заполнение каталога рядом с EXE не перезаписывает существующие файлы.


## Режим редактора проектов

Запуск из командной строки: `MDIAPP.exe engine`. Например, в PowerShell из каталога сборки: `.\MDIAPP.exe engine`.
Первый аргумент `engine` не зависит от регистра. В этом режиме «Настройки → Двигатели» открывает окно «Настройки проекта»: список двигателей слева, настройки выбранного проекта справа. Без аргумента тот же пункт открывает выбор двигателя.
В Visual Studio 2019 аргумент задаётся в свойствах запускаемого проекта, «Отладка → Аргументы командной строки»: `engine`.
«Применить» сохраняет настройки, OK сохраняет и закрывает окно. При переключении двигателя предлагается сохранить текущие изменения. Удаление снимает регистрацию проекта, файлы двигателя остаются на диске.


Проекты двигателей создаются непосредственно рядом с MDIAPP.exe: <каталог EXE>\Test. Комплект Data используется для первоначального заполнения отсутствующих файлов. Старые данные в LocalAppData автоматически не перемещаются.

В настройках проекта панели ограничены по минимальной ширине кнопок; прокрутка находится в таблицах. Верхние отдельные поля удалены. Описание двигателя редактируется в колонке Наименование, конфигурации — в ячейках таблицы. Нижние кнопки Применить сохраняют все настройки без закрытия окна.

В списке двигателей кнопка «Редактировать» заменяет «Импортировать». Открывается общая форма создания/редактирования с текущими данными и путями bin/data/namepar1.txt/PROJECT.BMP. OK обновляет выбранный проект, поддерживает изменение имени папки и номера, а также добавление/замену импортируемых файлов; остальные файлы сохраняются. Перед обновлением остаётся полная резервная копия <старое имя>.backup-<идентификатор> рядом с проектом. Отмена формы не меняет проект. Очистка поля изображения при редактировании сохраняет существующую картинку.
